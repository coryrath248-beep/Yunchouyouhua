## 2. 本聊天确认的核心要求

以下要求是后续修改时必须继续遵守的约束。

### 2.1 环境与阶段范围

1. 使用 Unity `2022.3.62f3c1 LTS`。
2. 第一阶段先完成 Unity 本地仿真、视觉效果和整线逻辑。
3. ROS、MQTT 或其他通信协议属于第二阶段，本阶段不强制接入。
4. 当前项目必须能够不依赖 Broker、Python 后端或 ROS 节点独立演示。

### 2.2 场景与视觉要求

1. 默认应展示整个车间的全局视角，不能长期只聚焦某一个机器人。
2. Game 画面应保持清晰，避免早期截图中严重模糊、过曝和构图拥挤的问题。
3. 机械臂夹爪必须位于末端执行器上，不能悬浮在机器人顶部。
4. 货物、夹爪、载具、机床和输送设备之间不能出现明显穿模。
5. 运行时不得通过全局键盘模拟误触浏览器、Gemini 或系统打印界面；自动化操作只能定向发送给 Unity 窗口。

### 2.3 仓储与物流要求

1. 使用车间顶部的大型共享立体仓库 ASRS。
2. 严禁给每一个 ROS/机器人单独创建小货架。
3. 大货架、堆垛机、出库输送台、中央配送载板和机器人必须组成一套同步运行的流水线。
4. 第一件货物被取走后，后续货物应由大货架继续补充到出库/配送位置。
5. 配送载板必须在机械臂真正夹取货物以后再返回货架端。
6. 货物必须由真实夹爪接管，不能提前瞬移或出现“幽灵递交”。
7. 成品不能落在机器人行走轨道或中央物流轨道上，必须进入明确的成品托盘区。

### 2.4 加工流水线要求

1. 三条生产线都要运行，不能只做单个 ROS 的局部演示。
2. 每条线使用同一个真实工件对象依次经过仓库、机器人、机床、输送机和成品区。
3. 工件不能在装载时消失，也不能创建重复的“替身货物”。
4. 机器人运动不能左右摇摆或在装载位置反复颤动。
5. 机床装载、加工、卸载、输送机交接和最终出料必须构成连续闭环。

## 3. 快速执行方式

### 3.1 从 Unity 编辑器启动

在 PowerShell 中执行：

```powershell
& 'D:\Program Files\Editor\Unity.exe' `
  -projectPath 'C:\Users\lyj\Desktop\面相柔性机加工车间的人机协同\TsinghuaFactoryTwin'
```

Unity 打开后：

1. 在 Project 面板打开 `Assets/Scenes/FactoryMachiningTwin.unity`。
2. 等待右下角资源导入和脚本编译完成。
3. 确认 Console 没有红色编译错误。
4. 点击顶部三角形 `Play`。
5. HUD 显示 `OFFLINE DEMO` 属于当前阶段的正常状态，不要求 MQTT 在线。

### 3.2 正常运行时应观察到的流程

```text
大型共享货架
  → 堆垛机取货
  → ASRS 出库输送台
  → 中央配送载板
  → 载板到对应生产线并停车等待
  → 机械臂夹爪确认接管
  → 空载板返回
  → 机器人送入机床
  → 机床加工
  → 机器人卸料
  → 中间输送机交接
  → 下一机器人接管
  → 最终质检工位
  → 对应生产线的成品托盘
```

事件流中应依次出现类似信息：

```text
ASRS RETRIEVAL
DISTRIBUTION HANDOFF
GRASP CONFIRMED → SHUTTLE RETURN
LOAD
PROCESSING
QC PASS → FINISHED GOODS
```

### 3.3 停止

点击 Unity 顶部已经变蓝的 `Play` 按钮退出运行模式。正常停止不会修改场景文件。

### 4.8 穿模、颤动与“幽灵递交”修正

- 取消货物和载板之间相互挤压造成的视觉颤动。
- 堆垛机货物使用独立货物锚点，避免货物与黄色升降部件重叠。
- 配送载板使用等比例独立锚点，避免父对象非均匀缩放导致货物变形。
- 取货阶段夹爪未到位前，工件保持在原设备或载板上。
- 卸货阶段夹爪未到位前，工件保持固定在机器人载具上。
- 只有夹爪实际到位时，工件所有权才切换到 `OnGripper`。
- 夹爪确认接管后才发送 `GRASP CONFIRMED → SHUTTLE RETURN`。

### 4.9 全局视角与画质

- Game 视图保持 1x 显示和较清晰的全局构图。

### 4.10 第三阶段稳定性重构

新增工件生命周期状态：

```text
InRack
→ OnStacker
→ OnConveyor
→ AtHandoff
→ OnGripper
→ OnRobot / InMachine / OnConveyor
→ Finished
```

具体修改：

- 每个工件具有唯一 `MaterialId`、当前状态、所有者、状态变更序号和变更时间。
- 非法状态跳转会被拒绝并输出错误。
- 暂停/恢复时会修正阶段起始时间，避免恢复后瞬移。
- 生产线暂停时同步暂停仓库流程。
- 新增 `FactoryFlowIntegrityMonitor`，每 0.5 秒检查一次：
  - 工件 ID 缺失或重复；
  - 所有者缺失；
  - 工件越出厂区；
  - `OnGripper` 工件未挂在 `Grip Anchor`；
  - `OnRobot` 工件未挂在 `Payload Carrier Anchor`；
  - `Finished` 工件未进入成品根节点；
  - 成品错误进入中央物流轨道。

- Unity 运行异常：`0`。
- 生命周期完整性违规：`0`。

### 4.11 成品掉落到轨道问题

问题原因：

- 旧成品坐标约为 `x=23.35`。
- 中央物流轨道位于 `x=22.82` 和 `x=23.48`。
- 因此程序会把完成加工的货物直接摆到中央物流轨道走廊中。

修复内容：

- 为三条生产线分别创建可见的成品托盘。
- 每个托盘提供 10 个循环槽位。
- 成品落点移动到对应产线末端机械臂内侧。
- 成品位置避开机器人水平轨道和中央纵向物流轨道。
- 完整性监控增加 `finished-on-rail` 检查。

验证结果：

- 事件流出现 `QC PASS → FINISHED GOODS`。
- 白色成品正确停在三条线对应的托盘上。
- 中央物流轨道保持空闲。
- 运行错误与完整性错误：`0`。

- [x] 不存在每台机器人附带的小货架。
- [x] 配送载板到站后停车等待。
- [x] 夹爪到位前货物不提前离开载板/载具/机床。
- [x] 夹爪接管以后空载板才返回。
- [x] 货物在机器人载具上保持可见。

- [x] 成品落到对应生产线的成品托盘。
- [x] 成品和在制品均不占用物流轨道。
- [x] Console 无 `Factory Flow Integrity` 错误。
- [x] 自动化操作没有影响浏览器或弹出打印界面。

建议每次结构性修改后至少连续运行 100 秒，涉及库存循环或长期稳定性时应运行 30 分钟以上。

## 8. 修改纪律

后续开发不得破坏以下规则：

1. 不重新创建每机器人独立小货架。
2. 不用隐藏、销毁或复制货物来掩盖交接错误。
3. 不让工件在没有夹爪接触的情况下切换到机器人。
4. 不将成品、在制品或配送载板停在轨道通行区域。
5. 不用全局 `SendKeys` 或鼠标模拟控制 Unity，以免影响浏览器和其他应用。
6. 不在第一阶段擅自扩大到 ROS/MQTT 通信实现。
7. 每次修改必须至少完成编译检查、实际 Play 检查和错误日志检查。
